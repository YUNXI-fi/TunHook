# TunHook 组网功能技术设计（v1）

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 异地组网（模块 id：`mesh`） |
| 目标版本 | v1，单网络实例 |
| 运行环境 | fnOS，root 运行 |
| 技术底座 | EasyTier（独立进程，非二次开发） |
| 设计状态 | 待评审，未开始编码 |

### 1.1 关键决策摘要

1. 组网内核用 EasyTier，以独立进程运行，TunHook 不修改其源码。
2. v1 只支持一个网络实例；多站点通过“同一网络 + 各自发布子网”实现。
3. v1 只使用 EasyTier 内置 NAT，不修改 `ip_forward`，不创建 nft/iptables 规则。
4. 内核二进制随安装包分发，首次启动不依赖外网。
5. 仅 root 版可用；非 root 环境明确提示不可用。
6. 默认不发布任何本机网段，发布必须二次确认。
7. 手机/电脑不作为 v1 客户端；NAS 之间组网，其他设备通过 NAS 访问。

## 2. 背景与目标

TunHook 现有能力集中在“把某个端口或网站暴露出去”：端口转发、FRP、Cloudflare Tunnel、STUN 打洞。它们解决的是“访问某个服务”，不解决“多台 NAS 所在的内网像同一个局域网一样互访”。

本功能要补齐后者：

1. 多台 fnOS/NAS 加入同一个虚拟网络，各自获得固定的虚拟 IPv4。
2. 每台 NAS 可以把本机所在的局域网网段发布到虚拟网络，其他节点自动获得路由，实现站点到站点互访。
3. 两端内网网段相同（例如都是 `192.168.1.0/24`）时，支持映射到不同虚拟网段，不改物理网络。
4. 没有公网 IP 也能用：优先 P2P 打洞，失败时走中继。
5. 不改变现有端口转发、FRP、网关、Web 服务的运行方式。

### 2.1 非目标（v1 不做）

- 不做手机/电脑的原生客户端。NAS 之间组网；其他设备通过 NAS 访问。后续可用 EasyTier 的 WireGuard 门户接入标准 WireGuard 客户端。
- 不做多网络实例（一个 TunHook 同时加入多个虚拟网络）。多站点用同一个网络 + 各自发布子网即可。
- 不做出口节点（`exit_nodes`）和全局代理。
- 不做系统内核转发模式（`proxy_forward_by_system`）。v1 只用 EasyTier 内置 NAT，避免改 `ip_forward` 和 nft 规则。
- 不自研 mesh 协议，不改造现有 STUN 打洞模块。
- 不做 IPv6 组网、MagicDNS、ACL 细粒度策略。

## 3. 技术选型

### 3.1 结论

使用 EasyTier 作为组网内核，TunHook 负责配置、进程守护、状态展示和生命周期管理。

### 3.2 对比

| 方案 | 适配度 | 主要问题 |
| --- | --- | --- |
| EasyTier | 高 | 项目较年轻；公共中继质量不可控；LGPL-3.0 |
| Tailscale / Headscale | 中 | 依赖账号或自建协调服务器；跨平台客户端优势在“仅 fnOS”场景用不上 |
| ZeroTier | 中 | 依赖控制器/账号；License 与分发限制 |
| WireGuard | 低 | 本身没有 NAT 穿透，必须有公网可达 hub |
| 自研 | 低 | 需要中继、路由、密钥、NAT 类型适配，工作量和稳定性风险都过高 |

### 3.3 选择理由

- 原生子网代理和自动路由，正好覆盖“站点到站点”。
- P2P 打洞 + 中继兜底，无公网 IP 可用。
- 支持自建共享节点，不强制依赖第三方账号。
- 单二进制、静态链接，和现有 frpc/cloudflared 的外置内核模式一致。
- `easytier-cli` 提供节点、对端、路由状态，便于做 UI。
- 默认 AES-GCM 加密，支持私有模式。

### 3.4 License 处理

EasyTier 使用 LGPL-3.0。TunHook 只以独立进程方式调用未修改的官方二进制，不链接其代码、不修改其源码。分发时：

- 安装包内附 `LICENSE-EasyTier` 和 `NOTICE`，写明版本、来源、许可证。
- 在“关于”页或文档中提供源码获取地址。
- 如果未来修改 EasyTier 源码，必须按 LGPL 公开修改部分。

## 4. 总体架构

```text
Svelte 页面 (Mesh.svelte)
        |
        | /api/mesh/*
        v
Go web 层 (mesh_handlers.go)
        |
        v
mesh.Manager
  ├─ 配置校验 / TOML 生成
  ├─ 进程启动 / 停止 / 看门狗
  ├─ easytier-cli 状态采集
  └─ 网段冲突检测
        |
        +--> easytier-core -c mesh.toml
        |        |
        |        +--> TUN 虚拟网卡（虚拟 IP）
        |        +--> P2P / 中继 / 子网代理
        |
        +--> easytier-cli（本地 RPC 127.0.0.1:15888）
```

数据流：

- 本机 LAN 设备 → NAS 的 TUN → EasyTier 虚拟网络 → 对端 NAS 的 TUN → 对端 LAN。
- 子网代理由 EasyTier 自动同步路由；TunHook 只负责把“要发布哪些网段”写进配置。
- 状态由 `easytier-cli` 读取，TunHook 不直接解析协议报文。

## 5. 功能范围与交互

### 5.1 v1 功能清单

1. 创建/编辑一个组网配置。
2. 启动、停止、重启组网进程。
3. 查看运行状态、虚拟 IP、对端列表、路由表、日志。
4. 选择本机要发布的局域网网段；支持重复网段映射。
5. 配置 Peer/共享节点、监听端口、虚拟 IP、MTU。
6. 随应用自启（可开关）。
7. 模块管理里可关闭“异地组网”入口。
8. 仪表盘卡片展示组网状态。
9. 备份导出/恢复组网配置。
10. 内核二进制随安装包分发，支持离线使用。

### 5.2 页面状态

| 状态 | 判定 | 页面表现 |
| --- | --- | --- |
| 未配置 | 无 `mesh.config` 或网络名为空 | 显示引导，主按钮“开始配置” |
| 已停止 | 有配置，进程未运行 | 显示配置摘要，主按钮“启动” |
| 启动中 | 已拉起进程，等待 RPC/TUN 就绪 | 禁用按钮，显示进度与超时提示 |
| 运行中 | 进程存活且 `easytier-cli node` 可读 | 显示虚拟 IP、对端、路由、流量 |
| 异常 | 进程退出或 RPC 不可达 | 显示错误原因与“重启/查看日志” |
| 不可用 | 非 root、无 `/dev/net/tun`、二进制缺失 | 显示明确原因，禁用启动 |

### 5.3 首次配置向导

1. **网络标识**：网络名、网络密钥、本机虚拟 IPv4、主机名。
2. **连接方式**：默认使用共享节点；可添加自定义 Peer；可修改监听端口。
3. **发布网段**：从本机网段列表多选；可选“映射为”；默认不发布任何网段。
4. **确认**：展示“将对虚拟网络暴露哪些网段”，二次确认后保存并启动。

## 6. 数据模型

### 6.1 存储位置

使用现有 SQLite `settings` 表，key 为 `mesh.config`，value 为 JSON。无需新建表，升级无需 schema 迁移。

运行时状态不持久化；仅持久化用户配置。

### 6.2 配置结构

```json
{
  "auto_start": false,
  "network_name": "tunhook-home",
  "network_secret": "********",
  "virtual_ipv4": "10.144.144.2",
  "dhcp": false,
  "hostname": "fnos-home",
  "peers": ["tcp://1.2.3.4:11010"],
  "listeners": ["tcp://0.0.0.0:11010", "udp://0.0.0.0:11010"],
  "proxy_networks": [
    { "cidr": "192.168.1.0/24", "map_to": "" }
  ],
  "manual_routes": [],
  "mtu": 0,
  "dev_name": "tun0",
  "private_mode": true,
  "latency_first": false,
  "disable_ipv6": false,
  "use_smoltcp": true
}
```

字段说明：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `auto_start` | bool | false | 应用启动后是否自动拉起 |
| `network_name` | string | 空 | 虚拟网络标识，同一网络必须一致 |
| `network_secret` | string | 空 | 网络密钥，API 不返回明文 |
| `virtual_ipv4` | string | `10.144.144.2` | 本机虚拟 IP |
| `dhcp` | bool | false | 是否由 EasyTier 自动分配虚拟 IP |
| `hostname` | string | 系统主机名 | 对端列表显示名 |
| `peers` | string[] | `[]` | 初始 Peer 地址，如 `tcp://host:11010` |
| `listeners` | string[] | TCP/UDP 11010 | 本机监听地址 |
| `proxy_networks` | object[] | `[]` | 要发布的局域网网段；`map_to` 非空表示映射 |
| `manual_routes` | string[] | `[]` | 高级：只把指定网段交给虚拟网络；为空表示自动 |
| `mtu` | int | 0 | 0 表示使用 EasyTier 默认值 |
| `dev_name` | string | `tun0` | TUN 接口名，需避免与现有网卡冲突 |
| `private_mode` | bool | true | 不允许其他网络借本节点中转 |
| `latency_first` | bool | false | 延迟优先选路 |
| `disable_ipv6` | bool | false | 是否禁用 IPv6 |
| `use_smoltcp` | bool | true | 用用户态协议栈做子网代理，避免依赖系统防火墙放行 TUN；TCP 性能略低 |

### 6.3 密钥处理

- `network_secret` 存在数据库和 `mesh.toml` 中，权限 `0600`。
- API `GET /api/mesh/config` 只返回 `has_secret: true`，不返回明文。
- `POST /api/mesh/config` 中 `network_secret` 为空表示“保持原值”，非空表示更新。
- 日志、进程参数、错误信息中不得出现密钥。
- 存储级别与现有 frp token 一致；如果后续要更高安全级别，可复用备份功能的设备密钥加密。

## 7. 配置生成与进程管理

### 7.1 文件布局

```text
@appdata/TunHook/mesh/
  easytier-core          # 从安装包复制，0755
  easytier-cli           # 从安装包复制，0755
  version                # 当前内核版本
  mesh.toml              # 生成配置，0600
  mesh.pid               # 进程 PID
  logs/                  # EasyTier 自身文件日志（自动轮转）
```

日志使用 EasyTier 自带文件日志，避免和主日志轮转逻辑重复实现：

```text
--file-log-level info
--file-log-dir <dataDir>/mesh/logs
--file-log-size 20
--file-log-count 2
```

### 7.2 TOML 生成

- 使用 `github.com/pelletier/go-toml/v2` 序列化。
- 字段名以锁定版本的 `easytier-core --help` 和配置助手导出为准；首次接入时生成一份 golden fixture 存入测试。
- 网络密钥只写入 TOML，不放在命令行参数里，避免 `ps` 泄露。
- 生成前先写临时文件，`fsync` 后原子 rename，权限 `0600`。

字段映射（最终以锁定版本为准）：

| TunHook 字段 | EasyTier 配置项 |
| --- | --- |
| `network_name` / `network_secret` | `network_identity.network_name` / `network_identity.network_secret` |
| `virtual_ipv4` | `ipv4` |
| `dhcp` | `dhcp` |
| `hostname` | `hostname` |
| `peers` | `peer[].uri` |
| `listeners` | `listeners` |
| `proxy_networks[].cidr` | `proxy_network[].cidr` |
| `proxy_networks[].map_to` | `proxy_network[].cidr` 的映射写法（`原网段->映射网段`，字段名以锁定版本为准） |
| `manual_routes` | `manual_routes` |
| `mtu` | `mtu` |
| `dev_name` | `dev_name` |
| `private_mode` | `private_mode` |
| `latency_first` | `latency_first` |
| `disable_ipv6` | `disable_ipv6` |
| `use_smoltcp` | `use_smoltcp` |
| 固定值 | `rpc_portal = "127.0.0.1:15888"` |
| 固定值 | `encryption_algorithm = "aes-gcm"` |

### 7.3 启动命令

```bash
<dataDir>/mesh/easytier-core \
  -c <dataDir>/mesh/mesh.toml \
  --rpc-portal 127.0.0.1:15888 \
  --console-log-level info \
  --file-log-level info \
  --file-log-dir <dataDir>/mesh/logs \
  --file-log-size 20 \
  --file-log-count 2
```

### 7.4 进程管理

沿用 `frpc.Manager` 的模式：

- `exec.Command`，`SysProcAttr{Setpgid: true, Pdeathsig: SIGTERM}`。
- stdout/stderr 写入 `<dataDir>/mesh/logs/core-console.log`，启动前若该文件超过 20MB 则滚动为 `.1`；主要日志仍以 EasyTier 文件日志为准。
- 启动成功后写 `mesh.pid`。
- `Wait` goroutine 清理内存 cmd 和 pid 文件。
- 停止时先向进程组发 `SIGTERM`，等待 10 秒，超时 `SIGKILL`。
- 使用 `procutil.AliveAs` 校验 PID 确实属于 `easytier-core`，避免 PID 复用导致误杀。
- 进程控制按 Linux 实现；若项目需要保留 Windows 构建，把 `SysProcAttr` 放进 `proc_linux.go`，Windows 版本直接返回 `MESH_TUN_UNAVAILABLE`。
- 进程停止后 TUN 由内核自动删除；v1 不修改 nft/ip_forward，因此没有额外系统规则需要清理。

### 7.5 启动流程

1. 读取并校验配置。
2. 检查 root、`/dev/net/tun`、二进制、端口占用、网段冲突。
3. 确保二进制已安装且版本匹配。
4. 写入 `mesh.toml`。
5. 若已有进程，先停止。
6. 启动进程，写 PID。
7. 轮询就绪（最多 15 秒）：
   - 进程存活；
   - `easytier-cli node` 可读；
   - 返回的虚拟 IP 与配置一致。
8. 就绪后返回运行状态；超时则保留进程并返回错误，页面可查看日志。

### 7.6 停止流程

1. 设置运行期望状态为“停止”，看门狗不再自动拉起。
2. 向进程组发 `SIGTERM`。
3. 最多等待 10 秒，超时 `SIGKILL`。
4. 清理 PID 文件。
5. 返回停止状态；TUN 由内核回收。

### 7.7 看门狗

- 每 10 秒检查一次进程存活。
- 仅在 `auto_start=true`、配置有效、且用户没有手动停止时自动重启。
- 退避：5s、10s、20s、40s、60s，稳定运行 5 分钟后重置。
- 连续失败超过 5 次后停止自动重启，页面上报“自动恢复失败”，等待用户处理。
- 不通过 `easytier-cli` 判断“网络是否通”，只判断进程存活；P2P/中继重连由 EasyTier 自己处理。

### 7.8 随应用自启

- 挂到 `web.Server` 的后台启动流程，延迟 40 秒，晚于 frpc（30 秒）和 MEFrp（35 秒），避开开机高峰。
- 只读取 `auto_start`，不改变用户上次手动停止的意图（手动停止只影响当前运行期）。
- 失败仅记录日志，不阻断 TunHook 主服务。

## 8. 网络与路由设计

### 8.1 虚拟网段

- 默认 `10.144.144.0/24`，与 EasyTier 默认一致。
- 第一个节点建议 `10.144.144.2`，后续节点 `.3`、`.4`。
- `dhcp=true` 时由 EasyTier 分配，页面仍显示实际虚拟 IP。
- 保存前检查虚拟网段是否与本机物理网段冲突；冲突时拒绝保存并建议改用 `10.210.0.0/24` 等。

### 8.2 发布本机网段

- 从本机网卡枚举 CIDR，排除：
  - 回环、链路本地、组播、未指定地址；
  - `docker*`、`br-*`、`veth*`、`tun*`、`tap*` 等虚拟网卡；
  - 虚拟网络自身网段。
- 默认不选任何网段，必须显式勾选。
- 允许手动输入 CIDR，但要做合法性、掩码长度、与本机网段包含关系校验。
- 发布前弹窗展示：网段、本机接口、可能暴露的服务范围。

### 8.3 重复网段映射

- 当两个站点都使用 `192.168.1.0/24` 时，各自配置映射：
  - A 站点：`192.168.1.0/24 -> 10.1.1.0/24`
  - B 站点：`192.168.1.0/24 -> 10.2.2.0/24`
- 校验映射前后掩码长度必须一致。
- 映射后的网段不能与虚拟网段、其他已发布网段重叠。
- UI 在“发布网段”表格中提供“映射为”列，留空表示不映射。

### 8.4 远端路由

- EasyTier 自动把其他节点的子网代理同步到本机，并自动加路由。
- 页面“路由表”只读展示：虚拟 IP、主机名、代理网段、下一跳、延迟、cost。
- 运行期如果发现同一网段被多个节点发布，页面给出警告，提示使用映射。

### 8.5 内置 NAT 与防火墙

- v1 使用 EasyTier 默认内置 NAT 处理子网代理转发。
- 不修改 `net.ipv4.ip_forward`，不创建 nft/iptables 规则。
- EasyTier 文档提示：子网代理会用到系统网络栈，Linux 上可能需要在防火墙放行 TUN 接口的 INPUT/OUTPUT。为了不在 fnOS 上改防火墙，v1 默认开启 `use_smoltcp`，用用户态协议栈处理子网代理，代价是 TCP 性能略低。
- 高级用户可关闭 `use_smoltcp`，此时需要自行放行 TUN 接口；关闭后如果子网互访不通，页面提示“检查 fnOS 防火墙对 TUN 的放行”。
- 优点：不需要用户理解网关/防火墙，卸载和崩溃后没有残留规则。
- 代价：用户态转发，大流量性能低于内核转发；v1 接受，后续再评估系统转发模式。

### 8.6 MTU

- 默认 0，由 EasyTier 决定（加密场景通常 1360）。
- 允许手动设置 1280-1500。
- 页面在高级设置中展示，默认折叠。

### 8.7 Peer 与共享节点

- 默认使用 EasyTier 公共共享节点发现对端。
- 允许用户添加自定义 Peer：`tcp://`、`udp://`、`ws://`、`wss://`。
- 允许只填 IP:端口，保存时补默认协议。
- 支持自建共享节点：用户把自建节点地址填入 Peer 列表即可。
- 页面明确提示：公共节点只负责发现和中继，带宽与稳定性不受 TunHook 控制。

### 8.8 监听端口

- 默认 `tcp://0.0.0.0:11010`、`udp://0.0.0.0:11010`。
- 保存/启动前检查端口占用。
- 允许修改，但至少保留一个 TCP 或 UDP 监听；否则只能作为纯客户端连接已有 Peer。
- 不自动修改 fnOS 防火墙；如果外部无法直连，P2P 会退化到中继。

## 9. 状态采集

### 9.1 数据来源

通过本地 `easytier-cli` 读取：

```bash
easytier-cli node
easytier-cli peer
easytier-cli route
```

固定 RPC 门户 `127.0.0.1:15888`，只监听回环地址。若锁定版本的 `easytier-cli` 支持指定 RPC 门户，则显式传入该地址；否则依赖其默认值，并在启动前检查 15888 未被其他实例占用。

### 9.2 采集策略

- 后端缓存 3 秒，避免页面轮询放大进程调用。
- 页面不可见时前端停止轮询；重新可见时立即刷新。
- 每次调用设置 3 秒超时，失败不阻塞 HTTP 接口。
- 解析失败时返回原始文本和 `parse_error`，页面展示“状态解析失败”，不崩溃。

### 9.3 解析兼容

`easytier-cli` 当前输出为 ASCII 表格。设计一个 `Parser` 接口：

- 锁定 EasyTier 版本；
- 每个版本一份 golden 输出 fixture；
- 单元测试覆盖字段解析；
- 升级版本时必须重新跑 fixture，避免字段变化导致 UI 空白。

后续如果 EasyTier 提供稳定的 JSON/RPC 接口，再替换解析层，不影响上层 API。

## 12. 安全设计

1. **网络密钥**
   - 最少 16 位，前端实时提示强度。
   - 只写不读；接口返回 `has_secret`。
   - 不写日志、不出现在命令行参数。
2. **RPC 门户**
   - 固定 `127.0.0.1:15888`，禁止 `0.0.0.0`。
   - 不对外暴露，不经过 fnOS 网关。
3. **私有模式**
   - 默认 `private_mode=true`，禁止其他网络借本节点中转。
4. **发布网段**
   - 默认不发布。
   - 发布前列出将暴露的网段，二次确认。
   - 页面明确提示：加入同一网络的节点可以访问这些网段。
5. **root 限制**
   - 非 root 运行时模块显示“仅 root 版可用”，启动接口直接返回 `MESH_NOT_ROOT`。
   - 不使用 setuid 辅助程序。
6. **防火墙**
   - v1 不修改系统防火墙。
   - 如果 fnOS 防火墙阻断 TUN 流量，页面提示用户放行，不自动改规则。
7. **备份**
   - 组网配置默认随备份导出。
   - 未加密备份时提示“将包含网络密钥”，由用户确认。

## 13. 兼容与冲突

| 冲突点 | 处理 |
| --- | --- |
| 端口 11010/11011/11012/11013 | 启动前检查；被占用时提示修改监听端口 |
| 端口 15888 | 固定 RPC；被占用时启动失败并提示“已有 EasyTier 实例占用” |
| 虚拟网段与物理网段重叠 | 保存/启动前拒绝 |
| 两个站点同网段 | 要求使用映射，不自动猜 |
| Docker 网桥 | 网段选择器默认排除 |
| 现有端口转发/网关 | 不共享监听端口；组网使用独立 TUN 和路由 |
| 现有 STUN/frpc/cloudflared | 互不影响，可同时运行 |
| fnOS 防火墙 | 不自动修改；失败时提示 |

### 14.1 安装包内容

```text
app/mesh/
  easytier-core
  easytier-cli
  version
  LICENSE-EasyTier
  NOTICE
```

- 版本锁定，构建时校验 SHA256。
- 采用 x86_64 版本；ARM 版本后续按 fnOS 平台扩展。
- 安装包体积预计增加约 30 MB（core + cli）。

### 14.2 首次安装

1. 启动时检查 `<dataDir>/mesh/easytier-core` 是否存在。
2. 不存在则从 `app/mesh/` 复制 core、cli、version。
3. 设置权限 `0755`。
4. 校验版本与 `version` 文件一致。

### 14.3 升级

- 应用升级后，`app/mesh/` 内版本可能变化。
- 应用启动时比较 `app/mesh/version` 与 `<dataDir>/mesh/version`。
- 若不同：停止旧进程，复制新二进制，保留 `mesh.toml` 和数据库配置，按 `auto_start` 决定是否启动。
- 不在进程运行中覆盖二进制，避免 `ETXTBSY`。

### 14.4 离线使用

- 二进制随包分发，首次启动不依赖外网。
- 后续可选增加“上传离线内核包”和“从镜像下载升级”，v1 不做。

### 14.5 构建脚本

- `build.sh` 增加检查：`app/mesh/easytier-core`、`easytier-cli`、`LICENSE-EasyTier` 是否存在。
- 缺失时直接失败并提示放置路径，避免打出不可用包。
- 版本号写入 `manifest` 的 `desc` 与 `CHANGELOG.md`。

## 15. 生命周期

| 阶段 | 动作 |
| --- | --- |
| 应用启动 | 清理残留 PID；校验二进制；`auto_start` 为真则延迟 40 秒启动 |
| 应用停止 | 停止 mesh 进程；TUN 由内核回收；不改数据库中的 `auto_start` |
| 应用升级 | 保留 `mesh.config`；停止进程；替换二进制；按需恢复 |
| 卸载 | 应用停止时进程已退出；无 nft/ip_forward 残留；数据目录按 fnOS 策略保留或删除 |
| 崩溃 | `Pdeathsig` 终止子进程；下次启动清理 PID 和异常状态 |

## 16. 可观测性

- **日志**：EasyTier 文件日志，目录 `<dataDir>/mesh/logs`，单文件 20MB，保留 2 份。
- **页面日志**：读取日志尾部，支持自动刷新。
- **状态**：进程存活 + RPC 可读 + 虚拟 IP 匹配，三者都满足才算“运行中”。
- **告警**：
  - 进程退出；
  - RPC 不可达；
  - 启动超时；
  - 同一网段被多个节点发布；
  - 使用公共中继。
- **不做**：v1 不接入 Webhook 通知，不持久化流量历史。

## 17. 测试策略

### 17.1 单元测试

- 配置校验：网络名、密钥长度、虚拟 IP、Peer URL、监听端口、CIDR、映射掩码。
- 网段冲突：虚拟网段 vs 物理网段、发布网段重叠、映射后重叠。
- TOML 生成：golden 文件比对，密钥不进入命令行。
- CLI 解析：每个锁定版本一份 fixture，覆盖正常/空/异常输出。
- 进程管理：用 fake 脚本模拟启动、退出、SIGTERM、PID 复用。
- 日志尾部读取与脱敏。

### 17.2 集成测试

- 无 TUN 环境下用 fake 二进制验证 API 启停、看门狗、错误码。
- 配置保存/读取/备份恢复。
- 模块开关：关闭后导航隐藏、仪表盘卡片隐藏。
- 应用重启后 `auto_start` 行为。

### 17.3 双机验收

两台 fnOS/NAS，位于不同局域网：

1. 同局域网两台节点能互相 ping 虚拟 IP。
2. 不同 NAT 环境下能建立 P2P；失败时走中继。
3. A 发布 `192.168.1.0/24`，B 能访问 A 内网设备。
4. B 也发布 `192.168.2.0/24`，A 能访问 B 内网设备。
5. 两端都是 `192.168.1.0/24` 时，通过映射互访。
6. 停止后虚拟网卡消失，无残留进程/PID。
7. 重启 fnOS 后按 `auto_start` 恢复。
8. 端口冲突、错误密钥、无效 CIDR 均有明确提示。
9. 应用升级后配置保留，二进制版本正确。
10. 与现有端口转发、FRP、Cloudflare Tunnel 同时运行互不影响。

## 20. 风险与待确认

### 20.1 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| fnOS 未开放 `/dev/net/tun` 或权限不足 | 功能不可用 | P0 实机验证；不可用时模块显示原因，不做降级欺骗 |
| 公共共享节点不稳定 | 中继慢/断 | 支持自建节点；页面提示；P2P 优先 |
| 两端同网段 | 路由冲突 | 强制映射，不自动猜 |
| `easytier-cli` 输出变化 | 状态解析失败 | 锁定版本 + golden fixture；解析失败展示原始文本 |
| LGPL 合规 | 分发风险 | 附许可证、来源、版本；不修改源码 |
| 包体积增加 | 下载/安装变慢 | 只随包一个架构；后续按需扩展 |
| 用户误发布内网 | 安全暴露 | 默认不发布；二次确认；页面持续提示 |
| fnOS 防火墙拦截 TUN 流量 | 子网互访不通 | 默认 `use_smoltcp` 规避；关闭时提示用户放行 TUN |
| 端口/路由冲突 | 启动失败 | 预检 + 明确错误码 |

### 20.2 待产品确认

1. 默认是否启用 EasyTier 公共共享节点，还是要求用户先填自建节点。
2. v1 是否要把 WireGuard 门户（手机/电脑用标准 WireGuard 接入）一起做。
3. 是否接受安装包增加约 30 MB。
4. 是否需要“多网络实例”（一个 TunHook 加入多个虚拟网络）。
5. 组网配置备份时，未加密备份是否允许包含网络密钥。
